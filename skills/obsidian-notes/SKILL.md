# Obsidian Notes

## ノート

- 指定がなければ `template/general_note` のテンプレートを使う。
- フロントマターの `description` に、そのノートの目的と扱う範囲を簡潔に記録する。未設定なら、既存の本文とユーザーの意図から補う。
- 本文を更新する前に `description` を確認し、ノート全体の目的と範囲を保つ。目的や範囲を変更する指示があれば、`description` も更新する。
- 不要な見出しを追加しない。
- `### tasks` で管理する項目は、Obsidian Tasks のタスク形式（例：`- [ ] タスク内容 🔼`）で書く。
- 各タスクの本文冒頭（チェックボックスの直後）に、そのノートのフロントマターの `icon` を付ける（例：`icon: 🎮` なら `- [ ] 🎮 タスク内容 🔼`）。
- `tasks` の各タスクには、Obsidian Tasks が認識する優先度を明示する（例：`🔼`）。優先度は省略しない。
- GitHub の Issue・PR・Map の番号は、Obsidian にタグとして認識される裸の `#3` 表記を避け、`Issue 3`・`PR 3`・`Map 3`、またはその表記をラベルにしたリンクで書く。本文・フロントマター・新規の `ai-log` に適用する。URL のフラグメントや Obsidian の見出し・ブロック参照に使う `#` は変更しない。
- `### content` をマスタとし、ノートの目的に沿った現在の情報を簡潔にまとめる。更新時はセクション全体の既存記述を今回の成果・判断と現在の根拠に照らして見直し、作業の経緯や検証の詳細は `ai-log` に記録する。
- 有効な情報は保持し、古い記述そのものを修正・置換・削除する。重複・矛盾する記述は統合し、全体が現在の情報として読める状態にする。
- フロントマターの `updated` はプラグインが自動更新するため編集しない。

## AI の作業ログ

- 原則として作業対象のノートに残す。
- デイリーノートにはログ行への埋め込み参照（`![[ノート#^ブロックID]]`）だけを残す。
- `ai-log` セクションに記録する。
- 各行に Zettelkasten 形式のタイムスタンプを付け、Markdown の箇条書きで記録する。
- 同じタイムスタンプのログは1行にまとめてもよい。
- 追記は [scripts/append_ai_log.py](scripts/append_ai_log.py) を介して行い、順序を保つ。呼び方は `--help` で確認する。
- 指示がない限り過去の `ai-log` を改変しない。
- 人間は読まない前提とし、自然言語である必要はない。

## タスクノート

`tags` に `task` を含むノートをタスクノートとして扱う。フロントマターは以下の意味で記録する。

- `status`: 完了した事実を表す20文字以内のラベル。
- `next_action`: 人間向けの次のアクションを20文字以内で記録。
- `next_action_detail`: AI が次のセッションで実行する最初の具体的手順。
