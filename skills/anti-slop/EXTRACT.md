# EXTRACT — 指摘から監査を改善する

指摘された文が果たしていた不要な働きを特定し、別の題材にも使える監査基準にする。

1. 原文、文書の目的・想定読者・共有済みの事情、指摘の理由を確認する。既存の本質テストで拾えるかを調べる。
2. 拾えるのに見逃した場合は、判定文か監査手順を具体化する。記録しただけでは改善完了としない。拾えない場合は、題材や言い回しに依存せず判定できる問いを作る。口調の好みや主張の正誤は、文章監査として一般化できるかを先に確かめる。
3. 修正案を元の事例・違う題材の事例・正当な説明に当てる。不要な説明を拾い、必要な根拠・入力の事実を残せる文面にする。既存テストと重なるものは統合する。
4. 本質テストは SKILL.md の該当する監査節、実行手順は同ファイルの手順に反映する。同じ内容は一か所に置く。事例・採点記録は開発側で管理し、通常の編集に読み込ませない。
5. 改訂後の手順で文章を編集し、指摘された問題が減り、保持対象が残ることを確認する。未検証の点は区別して報告する。
