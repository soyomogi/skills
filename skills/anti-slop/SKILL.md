# Anti-Slop

文書の目的と読者に必要な内容だけを書く。

1. 依頼と文書の用途から、目的・想定読者・その読者が既に知っている範囲を内部で定める。明示された読者と共有済みの事情を優先する。読者を判断できず、誰が読むかで削除内容が変わる場合だけ確認する。
2. 本文に残す題材の事実・判断とその理由、本人の言葉、変更禁止箇所を入力から内部で押さえて本文を書く。初めて読む人には、題材が何か分かる説明を残す。既知の背景説明は省き、理解・判断・実行・記録に必要な内容を残す。
3. 下の「文体監査」で各文と句を監査し、曖昧な表現を書き換え、情報を足さない句を削る。
4. 下の「文脈言及監査」で目的・読者の既知範囲・本文全体と照合する。必要な内容を担わない文は削り、配置の指定がある情報は指定先に置く。
5. 修正後の本文を入力と突き合わせ、保持対象の事実・判断とその理由、変更禁止箇所が残ることを確認する。各文が読者に必要な内容を担うかも確かめる。監査テストの該当箇所があれば修正する。監査過程は求められたときに示す。

文章への指摘では対象文章を直す。このskill自体の改善を明示的に依頼されたときだけ、[EXTRACT.md](EXTRACT.md) を読む。

## 文体監査

各文と句にテストを当て、該当箇所を書き換えるか削る。

- 汎用性: 題材を入れ替えるだけで使え、その題材についての答え・根拠・事実・手順を何も足していないか。
- 削除: その句や文を消しても、読者に必要な情報がすべて残るか。残るなら削る。
- 具体性: 評価や方針を述べる語が、何をどう変えるか・何が起きたかを曖昧にしていないか。対象・動作・条件が分かる言葉に直す。入力にある感想や実績は、その内容を保つ。
- 装飾: 強調や区切りが、情報のまとまりや探しやすさに役立っていないか。役立たない装飾を外す。

## 文脈言及監査

依頼から定めた文書の目的・読者を基準に、各文を監査する。

- 自己言及: 題材への答えに、制作・編集・監査の説明が入り込んでいないか。作業報告など、過程を伝える依頼では必要な経緯を残す。題材そのものの過去の結果や実績も残す。
- 目的: 文書の目的と読者に必要な内容から外れ、関連するだけの話や目的の宣言を足していないか。根拠や留保を残すなら、読者の理解・判断・実行・記録の何に必要かを確かめる。
- 配置: 情報の置き場所が依頼や対象文書の運用規則で指定されているか。指定があればそこへ置く。指定がなければ、必要な情報は本文に残す。
- 重複: 各文の主張と理由を、本文の既出内容と、想定読者に共有済みの事情に照らす。同じ内容の説明し直しは削る。依頼者との会話だけで共有した事情を、他の読者も知るとはみなさない。既知でも記録として必要な事実や判断は残し、比較に必要な参照は短くする。
