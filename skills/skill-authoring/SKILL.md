# Skill Authoring

## 手順

1. 目的・期待する振る舞い・適用範囲を定める。
2. 下の配置規則に沿って、各指示をskill本体に含めるか判断する。編集対象は原本とし、配布コピーと区別する。
3. 個別事例から再利用できる判断条件・完了基準を抽出する。その事例だけの操作列を一般規則にしない。実行に必要な具体的手順は残す。
4. descriptionを役割・呼び出し条件に合わせる。本文・参照先に必要な指示が届くか確認し、規則の重複を除く。
5. 変更時は管理元の手順に従って反映する。原本との一致・参照先への到達・期待する動作を検証し、確認済みと未検証の範囲を報告する。

## 配置規則

- 自身の呼び出し条件 → description。
- 呼び出し後の手順・判断基準・処理分岐・参照条件 → skill本体。手順と参照規則は混在してよい。
- 共通指示: skillの呼び出しに依存せず、適用範囲内で継続して使う指示 → skill本体の外。
- 条件付き指示: skillの呼び出しに依存せず、特定条件で適用する指示 → skill本体の外。
- 導入先補正: 外部から導入したskillの原本を変更せず、導入先で挙動を補正する指示 → 導入先で管理。
- hooks: 特定イベントで機械的に実行する処理 → skill本体の外。
- 本体外の配置・配布方式 → 各管理元に従う。

## 重複の判断基準

- 重複とは、同じ規則・手順・判断基準が複数の場所に実質的に書かれていること。文面の一致は問わない。
- 重複の判定は除去テストで行う。片方を取り除いて他方への参照に置き換えても、指示の内容（条件・範囲・強さを含む）が変わらないものだけを重複とする。食い違うものは重複として挙げない。
- 「〜は○○に従う」のような委譲・参照の言及は重複ではない。
- 分離が明示されているもの（適用除外の宣言など）は、重複ではなく意図的な分離として扱う。
- 判断が割れるものは断定せず、「要確認」とする。
- 重複の解消は、正本を1つに定め、他方から取り除く。
