# anti-slop の読者別テスト

対象は `skills/anti-slop/`。シナリオ内の案件・数値・会話はすべて検証用に作った架空の内容で、実際の作業記録ではない。

## 実行

1. `scenarios/` の3件を各2回、新規セッションで実行する。
2. 各回で新しい一時ディレクトリを作り、`skills/anti-slop/SKILL.md` と `EXTRACT.md` だけを `.agents/skills/anti-slop/` にコピーする。シナリオファイルや採点情報は置かない。
3. 実行側には、シナリオの `task` と `input` だけを渡す。`expected` は採点側だけが読む。実行設定でローカルの anti-slop skill の適用を指定する。
4. `codex exec --ephemeral --skip-git-repo-check --sandbox read-only` などで各回を起動する。skillの改善案を題材にした文書を作る試験なので、skill本体の編集や外部への投稿は行わない。
5. 回答全文と実行条件を一時ディレクトリに保存する。実行条件にはモデル・CLIバージョン・実行日・skillとシナリオのハッシュを含める。他skillも適用された場合はその名前を記録する。
6. 下の基準で採点し、結果を報告する。生成結果・実行ログ・採点記録はこのリポジトリに保存しない。

シナリオから実行用の入力を切り出す例（リポジトリルートで実行）:

```python
from pathlib import Path

scenario = Path("test-skills/anti-slop/scenarios/self-task.md").read_text()
prompt = "## task\n" + scenario.split("## task\n", 1)[1].split("## expected", 1)[0].rstrip() + "\n"
# promptだけを実行側へ渡す。expectedは含めない。
```

## 採点

- 読者適合: 用途から読者を推定し、明示された宛先・共有済みの事情を優先できたか。推定過程の説明を要求せず、本文の背景説明が適切に残るかで見る。
- 文体残存: 抽象的な評価、情報を足さない前置き・締めが残った件数。
- 文脈言及残存: 不要な作成経緯、共有済みの説明、効能の再説明が残った文数。
- 誤削除・事実欠落: `expected` の保持対象を落とした件数。同じ欠落を両指標に数えた場合は明記する。
- タスク不遵守: 本文以外の説明、依頼外のファイル編集・投稿などの件数。

残存箇所は原文と、SKILL.mdのどの監査項目に当たるかを記録する。新しい情報を落とさず、各シナリオの削除対象を除ければ合格。2回の結果を個別に示し、片方だけ成功した場合は安定した成功と扱わない。

この3件は、読者別の背景説明・判断理由・事実の保持を確認する。読者が不明で確認が必要になる分岐や、あらゆる文書での効果までは検証しない。skillやシナリオを変えた場合は、旧条件の結果と区別する。
