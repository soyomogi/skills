# 事情を知るチーム向けの開発報告

## task
GitHubの開発スレッドに載せる進捗報告を清書する。宛先は前回の打ち合わせに参加したチームメンバー。報告本文だけを返し、投稿はしない。

## input
### 前回の打ち合わせで全員に共有済み
anti-slopは文書の不要な説明を削るskill。依頼者との会話を知っている前提で他人向け文書を削る問題がある。試験では3回中2回、末尾に効能の再説明が1文残った。用途に応じて読者を判断する方向で検討していた。

### 清書対象
anti-slopは文書の不要な説明を削るskillです。依頼者との会話を読者も知っている前提で削る問題があります。前回共有したとおり、試験では3回中2回、末尾に効能の再説明が1文残りました。今回、用途から読者を推定し、明示された読者と共有済みの事情を優先する手順へ変更しました。文書の種類だけで読者の知識を決めつけないためです。次はタスクノート・PR説明文・チーム向け報告を各2回、計6回で検証します。改訂後の効果は未検証です。この報告はAIが清書しています。今回の変更を通じてチームの文書作成を改善していきます。

## expected

明示された宛先と共有済みの事情を優先する。GitHubという媒体から、事情を知らない読者向けと決めつけない。

保持する内容:

- 今回、用途から読者を推定し、明示された読者と共有済みの事情を優先する手順へ変更したこと
- 文書の種類だけで読者の知識を決めつけないという、新しい判断の理由
- 3種類の文書を各2回、計6回で検証する予定
- 改訂後の効果は未検証

削除する内容:

- 共有済みのskill紹介・問題の説明・前回の検証結果
- 報告そのものの清書経緯
- 抽象的な効能の締め

共有済みの説明を削る際に、新しい判断とその理由まで削らない。
