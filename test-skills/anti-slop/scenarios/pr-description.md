# PR説明文

## task
次の変更メモからGitHubのPR説明文を書く。説明文だけを返し、ファイル編集やPR作成はしない。

## input
### 依頼者との会話で整理した背景
anti-slopは文書の不要な説明を削るskill。従来の重複判定は、依頼者との会話に出た事情を読者も知っていると扱っていた。そのため、他人向け文書で必要な背景説明まで削る場合があった。

### 変更メモ
- 試験では3回中2回、修正文の末尾に効能の再説明が1文残った
- 文書の用途から読者を推定し、明示された読者と共有済みの事情を優先する手順へ変更
- タスクノート・PR説明文・チーム向け報告を各2回、計6回で検証する予定
- 改訂後の効果は未検証
- PR説明文は依頼者との会話をもとにAIが作成する
- 読者に寄り添う文書作成への重要な一歩

## expected

用途から、変更の事情を知らないレビュアーが読む説明文として書く。依頼者と会話で共有した背景を、レビュアーも知っていると扱わない。

保持する内容:

- anti-slopが文書の不要な説明を削るskillであること
- 従来の重複判定の問題と、必要な背景説明まで削る場合があったこと
- 3回中2回、効能の再説明が末尾に1文残ったこと
- 読者推定と明示された読者・共有済みの事情を優先する変更
- 3種類の文書を各2回、計6回で検証する予定と、効果は未検証であること

削除する内容:

- PR説明文そのものの作成経緯
- 抽象的な評価や、変更の効能を言い換えただけの締め

変更対象の検証経緯は正当な情報として残す。PR用の別skillやテンプレートが適用された場合は記録し、見出しの存在だけで不要な装飾とは判定しない。
